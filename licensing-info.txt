1.5  Silk.NET                     MIT        Direct3D 11 / DXGI / HLSL / OpenGL / math bindings
  - Silk.NET.Direct3D11                 2.22.0  (Ged.Rendering)
  - Silk.NET.DXGI                       2.22.0
  - Silk.NET.Direct3D.Compilers         2.22.0  (D3DCompile — runtime HLSL compilation)
  - Silk.NET.OpenGL                     2.22.0  (OpenGL 3.3-core cross-platform backend — L2)
  - Silk.NET.Maths                      2.22.0  (camera view/projection math)
  - Silk.NET.Core                       2.22.0  (pulled in transitively)
  (Silk.NET.SDL/GLFW windowing bindings are NOT referenced)
  https://github.com/dotnet/Silk.NET  (MIT License)
  Thin P/Invoke bindings over the OS Direct3D 11 and OpenGL runtimes; NO native
  binaries are redistributed for either. D3D11/DXGI/d3dcompiler ship with Windows;
  the OpenGL backend loads the system opengl32.dll (Windows) / libGL (Linux/Mesa)
  through a raw WGL / EGL / GLX context, so no GL native payload is bundled and the
  single-file publish stays clean. Silk.NET.OpenGL is pure managed bindings. The
  Linux offscreen (headless-test) context is created by GED's own raw P/Invokes to
  the system libEGL.so.1 / libGL.so.1 / libX11.so.6 (Mesa / X11) — these are
  system-provided, P/Invoked only, and NOT redistributed (exactly like D3D11 on
  Windows), so they add no new dependency or license obligation.

1.12  Native binaries redistributed (self-contained publish payload)
--------------------------------------------------------------------------------

A self-contained publish copies per-RID native libraries into
runtimes/<rid>/native/. For the shipped win-x64 target the following native
binaries are redistributed with GED. Each managed binding above is MIT, but the
*native* code has its own upstream license, recorded here:

  win-x64/native/Assimp64.dll        BSD-3-Clause  Open Asset Import Library (Assimp) 5.4.1
                                                   via Ultz.Native.Assimp 5.4.1
                                                   https://github.com/assimp/assimp
                                                   Copyright (c) 2006-2024, assimp team.
                                                   Ultz.Native.Assimp is the Silk.NET team's
                                                   native-binary packaging of it.

  win-x64/native/libSkiaSharp.dll    BSD-3-Clause  Skia 2D graphics library (Google)
                                                   via SkiaSharp.NativeAssets.Win32 2.88.8
                                                   https://github.com/google/skia
                                                   Avalonia's entire 2D UI is rendered by Skia.

  win-x64/native/libHarfBuzzSharp.dll  MIT         HarfBuzz text-shaping engine ("Old MIT"
                                     (Old MIT)     license, SPDX: MIT)
                                                   via HarfBuzzSharp.NativeAssets.Win32 7.3.0.2
                                                   https://github.com/harfbuzz/harfbuzz

  win-x64/native/av_libglesv2.dll    BSD-3-Clause  ANGLE (Almost Native Graphics Layer Engine),
                                                   Google's GLES-over-Direct3D layer that Skia
                                                   uses for GPU rendering on Windows
                                                   via Avalonia.Angle.Windows.Natives 2.1.22045.20230930
                                                   https://github.com/google/angle

For the shipped linux-x64 target the redistributed natives are:

  linux-x64/native/libSkiaSharp.so       BSD-3-Clause  Skia (Google) via SkiaSharp.NativeAssets.Linux 2.88.8
  linux-x64/native/libHarfBuzzSharp.so   MIT (Old MIT) HarfBuzz via HarfBuzzSharp.NativeAssets.Linux 7.3.0.2
  linux-x64/native/libassimp.so.5        BSD-3-Clause  Open Asset Import Library (Assimp) 5.4.1 via
                                                       Ultz.Native.Assimp 5.4.1 (the Silk.NET team's native
                                                       packaging). Silk.NET.Assimp's Linux name resolver loads
                                                       the versioned "libassimp.so.5" specifically.
  (No av_libglesv2 / ANGLE on Linux: Avalonia's Skia uses the system GL/EGL there, not ANGLE.)

Other runtime IDs present in runtimes/ (shipped only if that RID is targeted):
  win-arm64/, win-x86/ : same four natives (win-x86 uses Assimp32.dll).
  linux-arm/, linux-arm64/ : libSkiaSharp.so (BSD-3-Clause), libHarfBuzzSharp.so (MIT),
                        libassimp.so.5 (BSD-3-Clause).
  osx*/               : libSkiaSharp.dylib (BSD-3-Clause), libHarfBuzzSharp.dylib (MIT),
                        libassimp.5.dylib (BSD-3-Clause), libAvaloniaNative.dylib (Avalonia, MIT).
No Direct3D 11 / DXGI / d3dcompiler natives are redistributed — those ship with
Windows and are only P/Invoked by the Silk.NET bindings (§1.5).

1.13  Linux packaging (AppImage) — shipped runtime, build tool, first-party assets
--------------------------------------------------------------------------------

The Linux AppImage (dist/Glacier-<version>-linux-x86_64.AppImage, produced by
tools/package.ps1 via tools/appimage/build-appimage.sh) adds two format components
that the tar.gz and win-x64 zip do NOT contain:

  AppImage type-2 runtime   MIT     The small ELF (~0.9 MB) embedded at the head of the
  (embedded in .AppImage)           .AppImage that mounts the embedded squashfs and launches
                                    the app. appimagetool embeds it from the official AppImage
                                    project. SHIPPED as part of the .AppImage artifact only.
                                    https://github.com/AppImage/type2-runtime  (MIT)

  appimagetool              n/a     BUILD TOOL — NOT shipped, so it carries no redistribution
                                    obligation on the product. It is fetched once into the
                                    packaging host's home directory (never committed to the
                                    repo) to assemble the AppImage.
                                    https://github.com/AppImage/appimagetool

The AppImage's desktop entry (tools/appimage/Glacier.desktop), launcher script
(tools/appimage/AppRun), and application icon (Glacier.png, derived at build time from
src/Ged.App/Assets/AppIcon.png) are FIRST-PARTY GED assets under GED's own license
(LICENSE); §2b documents the icon-art provenance. No third-party desktop/icon
assets are used.

2. Adapted source code
--------------------------------------------------------------------------------

Portions of GED's Red Faction file-format code (RFL/RFG binary layout knowledge,
the geometry/brush/object data model, and reader/writer logic in
Ged.Core/IO and Ged.Core/Model) are derived from and inspired by REDUX
("The RED User eXperience Toolkit"), Copyright (c) 2025 Chris "Goober" Parsons,
distributed under the MIT License (https://github.com/GooberRF/redux). REDUX is
by the same author as GED; its code is reused and adapted directly under MIT.

Format layouts were additionally cross-checked against the community RFL/RFG
Kaitai Struct specifications, reverse engineered by Rafał Harabień (Open
Faction), wardd64 (Unity Faction), and Chris "Goober" Parsons (Alpine Faction
/ REDUX).

Alpine Faction (MPL-2.0) was used strictly as a *specification* for the Alpine
RFL section layouts and semantics, and for the ATX animated-texture descriptor
schema, the texture supercede chain, and the "Custom - <dir>" texture-category
behaviour. No Alpine Faction source code was copied; the layouts and semantics
were reimplemented from the documented field descriptions and format headers.

The DDS/BCn (BC1/BC2/BC3) block decoder, the TGA decoder, and the VBM decoder in
Ged.Core/IO/Tex are GED's own from-scratch implementations following the publicly
documented S3TC/DXT, Targa, and Volition-bitmap layouts. GED deliberately does NOT
depend on BCnEncoder.NET: a small built-in decoder keeps the dependency surface
minimal. The V3M/V3C mesh and VPP packfile knowledge is adapted from REDUX
(MIT, above) and the community format specs; the VPP padding rules were confirmed
empirically and against the RF.exe loader.

--------------------------------------------------------------------------------
2b. Object-icon assets (provenance)
--------------------------------------------------------------------------------

GED ships its OWN original object-icon set: the icons drawn in the viewport for
lights, triggers, events, regions, etc. are procedurally rasterized from simple
strokes/shapes at startup by Ged.Rendering.Graphics.IconAtlas. No copyrighted
game art is copied or distributed; these are authored line/shape drawings and are
covered by GED's own license (LICENSE).

The optional Settings ▸ Viewport toggle "Use original object icons (from game
files)" (default OFF) instead composites RED's *original* icon bitmaps
(Icon_Light.tga, Icon_Trigger.tga, the Alpine Icon_AFNote.tga / Icon_AFCorona.tga
/ Icon_EAX.tga, etc.) into the atlas. Those bitmaps are read at runtime FROM THE
USER'S OWN GAME FILES through the VFS (ui.vpp / alpinefaction.vpp) — exactly the
same way GED reads any level texture. GED never ships or redistributes RED's icon
bitmaps. Icons that fail to resolve fall back per-icon to GED's own drawn cell.
