❄⛏ Glacier Changelog ⛏❄
===================================

Version 1.3.0 (Beta 4): Not yet released
--------------------------------

### Major features
[@GooberRF](https://github.com/GooberRF)
- Added `glacier-cli`, Glacier's command-line tools, shipped beside the editor: run Lua scripts, build, check for holes, lint, summarize, and save levels from a terminal or an AI agent, with readable or `--json` output and documented exit codes. Builds and saves match the editor exactly, using your build method, lightmap method, and RF install from Settings.
- Command-line tools and AI agents can now drive the level open in the editor with `glacier-cli --attach`: script output appears in the Script Log, the viewport updates as changes land, and each run is one undo step labelled "CLI: <script>". Controlled by the new Settings option "Allow command-line tools and AI agents to control the open level".
- Scripting API version 2: scripts can now build and edit whole levels — create and edit any brush, place and configure any object, link, make movers and groups, place prefabs, set Level Properties, and tag what they make. Existing scripts run unchanged.
- Added the design kit (`ged.import("kit")`): rooms, corridors, doorways, stairs, ramps, sliding doors, platforms, pillars, lights, and spawn points that come out watertight and ready to edit by hand, plus a "tiny deathmatch level" example built with it.
- `ged.describe` and the Scripting API Reference document every member and every key of every option table (type, default, meaning); `kit.help()` does the same for the kit.
- Added organic spaces to the design kit: `kit.cave`, `kit.canyon` (open to the sky), and `kit.passage` follow a floor path on any heading, with rough rock walls, level or smoothly sloped floors, and a guaranteed 1.8 m wide, 2 m high walkway; `kit.rock_wall`, `kit.boulders`, and `kit.pit` add rock dressing and excavations, and `kit.light_path` lights a route. Everything they build compiles watertight under both build methods and stays hand-editable. The same generators are available to scripts as `geo.tube`, `geo.passage`, `geo.rock_row`, `geo.scatter`, and `geo.pit`. Two new examples under Scripts ▸ Examples show them in use: a snaking outdoor canyon and a cave network with a climb, a pit, and a loop.
- Added an agent guide, a ready-made Claude Code skill, and a new "AI-assisted level design" help section: an AI agent that can run command-line programs can build, check, and hand back levels you keep editing by hand. The guide ships in the `ai` folder beside the editor, and its examples are checked automatically so they stay accurate.
- Added `glacier-cli mcp`, a Model Context Protocol server, so AI assistants such as Claude Code and Claude Desktop can open, script, build, leak-check, lint, render, and save levels through typed tools instead of shell commands. Renders come back as images with their pixel-to-world mapping, every script run is one undo step labelled "AI: <script>", and what the assistant may do is set only by how the server is started (`--read-only`, `--allow-destructive`, `--allow-write`, `--tools`); it can never grant itself more. With the editor running, the server works on the level open there (or pass `--attach` / `--headless` to choose): you watch each change land and can undo any AI step, renders are drawn from a copy so they never touch your level, and it reconnects on its own if the editor is restarted. Discarding or overwriting work in the editor additionally needs the new Settings option "Allow destructive AI actions" (off by default).
- Glacier now reads and saves Alpine Faction 1.5 levels (RFL version 306). Every 1.5 level element loads and is written back exactly as stored: weather regions, vehicle factories, projection cameras, rope emitters, terrain, directional lights, vehicle waypoint helpers, mover paths, liquid glow, Alpine lightmaps, and the new lighting, sun, minimap, vehicle, far-clip, and Payload level properties. Weather regions, vehicle factories, projection cameras, rope emitters, directional lights, waypoint helpers, and terrain appear in the Outliner and in scripts (`level.objects_of("WeatherRegion")`, `o:get(...)`) as read-only objects; the status bar and Properties panel say so when one is selected.
- Saves now always write RFL version 306. Opening and saving an older level upgrades it the way Alpine RED does: the Alpine level properties gain the 1.5 settings at their defaults (with Alpine's lighting pipeline selected), Alpine meshes gain their 1.5 data, and a fog near clip that had no effect before is reset to 0 with a note in the save log.

- Added the design grader: `glacier-cli grade`, `design.grade{}` in Lua, and the MCP tool `grade_level` measure a level and check its scale, shape, flow, population, and texturing against limits calibrated on well-regarded stock and community levels, with CTF, King of the Hill, and Payload rules. The verdict is PASS, REVIEW, or FAIL, and every failing check comes with the measured values, a fix hint naming the design-kit helper to use, and the places to act on: chokepoint cells, dead-end pockets, bare and undressed areas, the longest sightlines, exposed spawns, and items too far apart or too far from the spawns. Open-air / floating-platform maps and Payload maps are recognized automatically and graded with their own limits; Payload maps also get per-leg checks, at least three routes into every next leg, and a spawn hand-off at every checkpoint.
- Added spatial queries for scripts and AI agents (`glacier-cli spatial`, the Lua `spatial` global, and the MCP tool `spatial_query`): raycast, line of sight, point info, and player clearance on the compiled level; floor reachable on foot, by lift, jump pad, or teleport, with the spawns and items nobody can reach; shortest and independent routes between two points; the layout's loops, chokepoints, and dead ends; sightlines and exposure; cover; dressing per area; spawn and item reports; and an area report that compares a region with the typical proportions of good levels. Every result says which build it measured (built, preview, or out of date), and measurements are cached and time-limited so they never hang the editor.
- Added whole spaces to the design kit: `kit.space` builds any of 19 archetypes at the scale of well-regarded multiplayer levels — a hall, atrium, arena, stacked ring, sunken court, stair hall, courtyard, canyon with a bridge, cave chamber, pit room, control room, or storage hall; open-air floating platforms, a sky bridge, or an open deck with full edge treatment; or a Payload cart road, overlook, gate, or fortified finale. Each one comes with its built structure (galleries, catwalks, stairs, daises, alcoves, racks, consoles, cover, parapets, canopies, trusses), builds watertight under both build methods, and returns attach points for doorways and roads; `kit.archetypes{}` lists them.
- Added generative fill to the design kit: `kit.dress` dresses rooms, corridors, caves, canyons, or any box of the level with a theme — industrial yard, construction site, storage, control room, mine, or outdoor canyon — placing detail props, free-standing cover with tall sightline breakers in larger spaces, ceiling beams, pipes or cable trays, wall pipe runs and panels, stock clutter (when the game tables are loaded), and stock decals. It keeps doorways, stairs, spawns, and items clear, never cuts a walking route, takes at most 1.5% of the walkable floor by default, and gives the same result for the same seed.
- Added `kit.items`, the item economy for deathmatch, team deathmatch, CTF, King of the Hill, control-point, and Payload layouts: about 1.6 items per 100 m² (fewer on large levels), weapons 7–10 m apart and spread over the layout, powerups in the most contested spaces and never in dead ends, health and armour on the flanks, an item near every spawn, CTF halves mirrored item for item, and Payload health and ammo along the cart route's flanks and at the defenders' holds.
- Added layout graphs to the design kit: `kit.layout{gametype, players, class, brief, seed}` plans a whole Deathmatch, CTF, King of the Hill, or Payload level before a single brush exists — zones with their archetype, size, storey, and palette, typed connections (corridors, doorways, stairs, ramps, drops, bridges, windows, lifts, cart roads), spawn groups, flags, the hill, and the payload track — sized for the player count, in standard (indoor) or open-air (floating platforms and sky bridges) style, and the same every time for the same seed. `kit.check_layout` lists every broken layout rule (dead ends, single routes, too few loops or storeys, repeated rooms, CTF lanes and flag spacing, KOTH approaches, payload gates and hand-offs) by zone and link, `kit.layout_preview` draws the plan as text, and `kit.build_layout` builds it watertight with lights, spawns, flags, the capture point, and a fully configured payload cart, checkpoints, and spawn hand-off. The agent guide's new "Layout first" section walks through it, including how to trace a sketch into a graph.

### Minor features, changes, and enhancements
[@GooberRF](https://github.com/GooberRF)
- Builds now split rooms and portals the way RED does where an air portal brush cuts a doorway through a wall: the doorway is a room of its own with a portal at each end, and portal brushes are applied after every other brush whatever their place in the brush order. Most stock levels built around air portals now have exactly RED's room and portal counts (ctf04 25 rooms and 36 portals, was 5 and 3; dm06 41 and 46, was 18 and 20; ctf06 86 and 124, was 28 and 20). Applies to both build methods.
- A solid that touches nothing (a floating island, a tower in a skybox, a free-standing pillar) is now built as a sub-room of the room around it, as RED does, instead of a separate room with no portals.
- Detail brushes that cross a portal now stay one sub-room.
- Builds now repair holes the way Alpine Faction's level editor does: cracks under 1 mm are welded, t-junctions split, collapsed faces and zero-width portal strips removed, misplaced portal faces put back in the right room, rooms split without a portal rejoined, and small flat wall gaps filled. On by default under Geometry ▸ Repair Holes When Building; detail brushes and movers are never changed, and the build report, `glacier-cli build`, the AI build tool, and script build reports list what was repaired.
- A level saved by a newer Alpine Faction than Glacier knows opens read-only: the editor shows a notice and marks the window title, `glacier-cli info` / `open` and the MCP `open_level` result report `readOnly` with a note, and every save (editor, Lua, command line, MCP) is refused so the newer content is never lost.
- Added the Alpine Faction 1.5 events Display_Projection, Climbing_Region_State, When_Destroyed, Rope_State, Mesh_Set_Scale, Payload_Handler, Payload_Checkpoint, and When_Setup_Ends, plus Weather_Region_State, with their fields and link targets. Gametype_Gate now offers all 16 gametypes, and Music_Start shows its Looping box.
- Saving an older level whose Play_Sound or Music_Start events have Looping set adds a save-log note: from version 306 Alpine Faction honours that box, so those sounds now loop.
- The linter accepts When_Destroyed links to detail brushes, warns when another event links to a brush or when When_Destroyed links to a non-detail brush, and warns when a Payload_Handler level still has Legacy Movers on.
- Levels that store their 1.5 lightmaps only for Direct3D 11 (no stock lightmaps section) load normally, and an incremental relight skips their surfaces instead of failing on them.
- `level.alpine` now also reports the Alpine 1.5 lighting, sun, minimap, vehicle, and far-clip properties (read-only).
- Added a structured level summary (`glacier-cli summary`, brief / normal / full) listing bounds, brushes, objects with positions and key properties, links, rooms with their portal neighbours, and lint counts.
- Added `glacier-cli render`: draws a level (or, with `--attach`, the level open in the editor) to a PNG — by default a floor plan of one storey with walls, a metric grid, scale bar, labelled object symbols, links, and a legend; also top/front/side, isometric, and free-camera views — and reports the exact pixel-to-world mapping with `--json`. Rendering never changes the level.
- Command-line runs can only write under the level's folder, the install's `user_maps`, the scripts library, or a path named on the command line, and never discard unsaved work in the editor without `--allow-destructive`.
- Script builds (`ops.build()` / `ops.light()`) now use your Geometry ▸ Build method and Lightmap Method exactly like the toolbar commands, and the viewport, build status, and Build Output update as soon as the script finishes.
- Added `ops.holes()` for scripts, returning the position of every leak found on a sealed build; `ops.check_holes()` still returns the count.
- The level linter now lists each geometry leak as its own finding with a Jump button that frames it in the viewport, and script lint findings expose their location (`has_location`, `pos`).
- Script property edits are validated exactly like the Properties panel (option names for lists, `{r, g, b}` colours, clear errors for wrong types, out-of-range values, and read-only fields), and `level.props` / `level.alpine` read and write Level Properties through the same code as the Level Properties dialog.
- Script links to a mover or one of its brushes are stored on the mover's start keyframe (the link the game follows); `link_many` reports which targets were refused and why.
- A script's edits to a mover's brushes are now copied into the mover automatically before it builds, lights, saves, or packages and when it finishes.
- Script errors, including the design kit's, now point at the line of your script that made the call and carry a separate hint; modules can raise the same errors with `ged.fail`.
- Design-kit textures match the texel density of Red Faction's own levels: every kit surface, rock included, maps at 64 pixels per metre of its texture's real size when an RF install is mounted (a 256 px texture repeats every 4 m, a 128 px one every 2 m), and at one repeat per 4 m without one. Set `kit.defaults.ppm = nil` to tile every texture at `kit.defaults.tile_metres` instead. Kit lights never end up inside pillars or other solids.
- Design-kit stairs now get an invisible collision ramp so players walk up them smoothly, kit doors close as smoothly as they open, and the new `kit.sky_room` builds an outdoor sky.
- Room effects (sky room, liquid room, ambient light) can now be placed and edited from scripts like any other object.
- Saving from the command line now builds the level's geometry first when it is missing or out of date (`--no-build` skips it with a warning), and the linter reports a level with brushes but no compiled geometry as an error and flags solid portal brushes.
- Brush and object queries can be looped over with `ipairs` directly, and `brush_query:set_face_flag` sets a face flag (such as show sky) on every upward, downward, or side face of a set of brushes in one step.
- Script tags are saved with the level and copied brushes keep them; levels without tags save exactly as before. Prefab placement from scripts only ever reads files from the prefab library folder.
- Added Lua modules: `ged.import(name)` loads your own modules from the scripts library's `lib` folder (once per run, in the same sandbox and undo step); module files are not listed as runnable scripts in the Scripts menu or command palette.
- Added `glacier-cli api`, which prints the Lua scripting reference for the installed build (`--member level.brush` for one entry, `--lua` for the completion stub), with no level or editor needed.
- Added `glacier-cli undo --attach`, which takes back the editor's latest command-line run (or the last few with `--steps`) and refuses rather than undo anything you did yourself.
- Added `glacier-cli light` (a sealed build plus lighting) and `run --build` / `run --light` to compile after a script and before saving.
- `glacier-cli summary` now shows the tags on every brush and object and counts each tag, so you can see at a glance what an agent or the design kit made.
- `level.objects_of` and `selection.of_kind` now accept the same kind names as `level.place` (such as `"respawn"` or `"corona"`).
- Scripts can now build free-form convex brushes from a list of points with `level.brush_from_points` (or hundreds at once, as one undo step, with `level.brushes_from_points`); every generated vertex lands exactly on a 1/1024 m grid so neighbouring pieces stay watertight, and `geo.check(brush)` reports whether any brush is closed, outward, convex, and planar.
- Scripts can roughen, twist, bend, and taper brushes (`geo.jitter`, `geo.twist`, `geo.bend`, `geo.taper`) and the results stay convex with flat faces: a deformed brush can be cut into pieces that meet on identical faces, so they compile watertight. Also added `geo.extrude`, `geo.bevel`, `geo.weld`, and `geo.snap` (the repair for float noise on hand-made or imported brushes).
- Scripts can import `.obj`, `.gltf`, `.glb`, `.fbx`, and `.dae` models with `level.import_mesh`, as detail brushes or as an Alpine mesh object; models are only read from the level's folder, `user_maps`, the scripts library, or a file named with `glacier-cli run --allow-import`.
- Scripts can check whether a level's textures ship with the game: `catalog.texture_info`, `catalog.textures{stock = true}`, and `assets.texture_sources()` report whether every player has a texture or where the file comes from (Alpine, another packfile, or a loose file).
- `glacier-cli run` now tags everything a script creates with the script name and a per-invocation session id (each editor connection is its own session; a tag the script sets itself wins) and lists the created UIDs; pass `--no-tag` to turn tagging off. Scripts run from the Script Editor or Console are never tagged.
- Added `glacier-cli analyze`, which measures a level from its compiled geometry and prints a fingerprint: floor area, headroom, clear widths, corridor and doorway sizes, stair risers and treads, floor levels, the room/portal graph, texture families, lighting, spawn and item spacing, and recurring event link patterns. The level is only read, never opened for editing or changed.
- Added `glacier-cli corpus sweep`, `snapshot`, `verify`, and `aggregate`: fingerprint a whole folder of levels (loose `.rfl` files and the levels inside `.vpp` packfiles) into a separate output folder and turn the results into percentile statistics. Level folders are strictly read-only — files are opened for reading only, the output folder can never be or sit inside a level folder, and `verify` re-hashes every file to prove nothing changed. Duplicates are counted once, autosaves and AI-generated levels are skipped, interrupted sweeps resume, and `--debug-render` draws plan images of the detected doorways, corridors, and stairs for checking.
- Glacier now ships corpus norms: how released Red Faction levels are typically proportioned (doorway and corridor widths and heights, headroom, clear floor width, light density, texture tiling, and more), as percentiles with one vote per level, measured against a curated reference set of well-regarded stock and community levels. Aggregates only — no level, author, or texture names. Read them with `glacier-cli norms` (`--metric opening.width`, `--compare level.rfl` to see where a level sits), from scripts with `catalog.norms(metric [, bucket])` and `catalog.norm_metrics()`, and through the MCP tools `norms` and `compare_to_norms` and the `glacier://norms` resources.
- The linter now adds up to six info hints when a level's proportions fall outside the typical range; each names the measurement, its typical p5–p95 range, and the level's own value. They never block a save, appear on explicit lint runs (Lint panel, `glacier-cli lint`, MCP, `lint.run()`), not the save-time check, and are skipped with a note on an unsealed preview build.
- Behaviour change: the design kit's default sizes now follow the corpus norms (kit version 3) — `corridor_width` 4 → 4.5 m, `corridor_height` 4 → 4.5 m, `door_height` 3 → 4 m, `light_spacing` 8 → 5 m (`door_width` stays 3 m, `tile_metres` stays 4 m). Scripts that rely on the old defaults get the new sizes; pass the size explicitly or set `kit.defaults.<name>` to keep the old one. Existing levels are not changed.
- Behaviour change: `box_map()`, `planar_map()`, `cylinder_map()`, `brush_query:box_map()`, and `box_map{}` without `ppm` or `tile` now map at the tiling a brush drawn in the editor gets (one repeat per 4 m) instead of 256 pixels per metre, so script-made brushes match hand-drawn ones by default. Pass a `ppm` number (for example `b:box_map(256)`) for the old scale; the editor's own texture tools keep RED's 256 px/m.
- `glacier-cli corpus aggregate --promote` regenerates the norms built into Glacier from a sweep (size-checked), and an optional curated level list forms the reference bucket.
- Added `glacier-cli inspect` (every property, link, and tag of one object or brush), `query` (find objects or brushes by kind, class, name, tag, or region, paged), and `catalog` (placeable kinds, class names, properties, and textures, with no level needed).
- Added `glacier-cli checkpoint` and `diff --since` with `--attach`, which remember the open level's structure and list exactly what was added, removed, or changed since, with each property's old and new value; and `glacier-cli redo --attach`, which re-applies what `undo --attach` took back and refuses anything you undid yourself.
- `glacier-cli run --label` adds a short description to the run's undo label, and `glacier-cli lint --min-severity` lists only warnings and errors (or only errors).
- `glacier-cli mcp` also gives assistants the agent guide, the scripting conventions, the Lua reference, the design kit, and a summary of the open level to read, plus ready-made prompts to block out a level from a brief, review a level without changing it, extend the open level, or fix leaks. The new help section "Connecting Claude Code (MCP)" shows how to connect an assistant, what its "AI:" undo steps are, and how to undo its work.
- Repeated renders through `glacier-cli mcp` reuse the Red Faction install's packfiles and the texture data already read instead of reopening every packfile for each image; each render still draws a fresh copy of the level, and a changed install is picked up on the next render.
- `geo.bend` pieces now meet on exact shared faces like twisted and tapered pieces, so bent brushes compile watertight; a bend needs at least 0.5° per piece, and asking for more pieces says how many fit.
- `kit.cave` and `kit.canyon` check that every kit room they run into is tall enough for the cave's crown or the canyon's rim, and name the room height to use instead of leaking along the room's ceiling edge.
- `kit.pit` now opens through floors at any height, structural rock walls sink just below a floor that is not on the 1/16 m grid instead of floating over it, and boulders scattered on a sloped floor reach down to it on their downhill side.
- A closed cave or canyon loop whose last leg climbs or descends now builds.
- The organic generators now steer clear of more geometry the compiler handles badly (faces folding almost flat, corners and edges passing within millimetres of each other, passages grazing existing walls), and when an existing brush is in the way the error says so and what to move.
- `level.brushes_from_points` refuses a call that would take more than a few seconds of hull building and says how to split it, and long organic builds stop promptly when a script is stopped.
- Added `ged.try(fn, ...)` for scripts: it returns `true` and `fn`'s results, or undoes everything `fn` changed and returns `false` and the error (message and hint), so a script can retry an organic generator with another seed instead of failing. Time limits and Stop still end the run, and the run is still one undo step.
- `glacier-cli mcp` now serves the agent guide one section at a time (`glacier://guide/index` lists the sections and their sizes, `glacier://guide/<section>` reads one), so assistants that cut long reads short can read all of it.
- The agent guide now shows the MCP tool for every `glacier-cli` step of the core loop, finishes the worked example with MCP tools as well as commands, and gives the same finishing order everywhere: a sealed build, a hole check until it is watertight, then bake the lighting and save.
- A cave or canyon started inside another one on the same line now explains that its walls line up with the other tube's walls and suggests joining at an angle or extending the existing tube, instead of pointing at floor heights.
- The level summary now reads "8 multiplayer spawns (8 usable by red, 8 by blue, 0 by bots)", since a spawn both teams use counts for each team, and its JSON adds `bothTeams`.
- Saving through `glacier-cli` or the MCP tools now reports the first save of a never-saved level as a Save As and adds `previousPath`, the file the level pointed at before the save.
- New levels (File ▸ New, `glacier-cli new`, the MCP `new_level` tool, and scripts run without a level) now start with Alpine RED's new-level settings: Legacy Cyclic Timers and Legacy Movers off and every other Alpine level property at Alpine's defaults. Before, a new Glacier level ran with the legacy timer and mover behaviour in game. Existing levels are not changed.
- The Payload rules (push speed, rollback, acceleration, checkpoint time bonus, heal and ammo rate, overtime grace, and the attacker and defender respawn delay modifiers) can now be edited in Level Properties and from scripts (`level.alpine` `payload_*` fields).
- The linter now runs every check Alpine Faction makes before it starts a Payload cart: one Payload_Handler linked to a One Way, non-rotating mover with at least two keyframes, Legacy Movers off, and each Payload_Checkpoint named by one cart keyframe other than the first. Each finding says what to change.
- The agent guide has a new Payload setup section: how to configure a Payload map from a script or AI agent (level settings, the cart, the handler, checkpoints, and their respawns).
- Added `kit.palette`: coherent sets of stock textures for a zone (industrial, bunker, admin, cave, or Mars base) covering floors, walls, ceilings, trims, posts, door frames, accents, and hazard stripes, with variants so neighbouring rooms differ and red/blue team keys for team maps.
- Added `kit.trim`: a room's wall kit in one call — a base band, a top band, posts every few metres, frames around every doorway and window through its walls, and hazard stripes along the open edges of kit platforms, with each strip's texture fitted to it.
- New texture tools for scripts and AI agents: `face:align_to_edge` lines a texture up on an edge (panels standing on the floor line, a frieze hanging from the ceiling), `face:wrap_from` continues a texture around a corner, and `brush:fit_faces` gives crates, panels, and doors one texture per face whatever their rotation.
- Kit stairs now start each tread's texture at its nosing and hang each riser's from it, and kit ramps run their texture up the slope without stretching.
- Added a "textured zones" example under Scripts ▸ Examples showing palettes, trims, and the new texture tools.
- Design-kit rooms follow the proportions of well-regarded levels: `kit.proportion` gives the height for a footprint (corridors 4–5 m, rooms 3.5–6 m, halls 6–9 m, atria 12 m and up, hubs at least twice the corridors that feed them), and `kit.room` uses it when the size leaves the height out.
- Added rooms that are not boxes: `kit.shaped_room` builds octagon, L, T, U, cross, or any polygon plans with chamfered corners and flat, stepped, gabled, shed, coffered, or beamed ceilings; `kit.alcoves`, `kit.pilasters`, and `kit.floor_section` add wall insets, piers, and raised or sunken floor areas.
- Added landmark structures to the design kit: `kit.bridge` (truss, arch, girder, or plank bridges that report their span, unsupported gap, and drop, and warn below landmark scale), `kit.truss`, `kit.beam`, and 25–40 m `kit.landmark` towers, pylons, and spires.
- Added `kit.opening`, which cuts windows, arches, rough mouths, and plain doors between two spaces; an opening, cave mouth, or canyon mouth wider than 0.8× the clear width of a space it joins, or taller than 0.8× its headroom, now warns that the two spaces would read as one.
- Added `kit.road`, which lays a wide Payload cart road along a path with graded legs, level turns, roofed tunnel legs, and a warning on grades steeper than 15%.
- `kit.cave` and `kit.canyon` now warn when less than 30% of their floor is level, and `kit.organic_report` reports the level-floor share and the built elements standing in a cave or canyon.
- Every design-kit placement rule reads the floor through one ground provider: `kit.ground_at` and `kit.ground_region` sample it, and `kit.ground_provider` lets a script supply its own.
- `kit.spawn_points` now spreads spawns over the rooms at least 8 m apart, beside cover or in alcoves, clear of doorways, facing the nearest way out instead of the room centre, and chosen so few spawns see each other; `checkpoint =` links a Payload spawn group to its checkpoint so it advances with the cart.
- `kit.light_room` now hangs every light under a visible fixture (a stock light when the game tables are loaded, otherwise a small full-bright lamp; lamp posts in rooms open to the sky) and lights a corridor with a single row every 4 m.
- `kit.light_room` lights a room open to the sky the way Red Faction's own outdoor maps are lit: a few strong lights on its edges (lamps on the walls, a lamp post beside each doorway) instead of a lamp post every few metres across the floor, with range and brightness raised so the floor stays as well lit, and a soft glow at each lamp. A post stands inside only where a large open area's edges cannot reach, and never on the way between two doorways.
- `kit.light_path` gives every light a fixture: a lamp on the wall, or a lamp post at the edge of the walkway where no wall is near (`fixture = false` for bare lights).
- `kit.spawn_points` measures spawn exposure on exactly the floor and samples the design grader uses, so the exposure it plans is the exposure the grade reports.
- `kit.dress`, `kit.items`, and `kit.spawn_points` accept a room's name (its `kit.name`) wherever they take a room record.
- `kit.dress`, `kit.spawn_points`, and `kit.items` now do their heavy work natively: dressing, spawns, and items for a whole 7,000 m² level fit in one script run of about 17 seconds (instead of stopping at the instruction limit after a minute), and a 20,000 m² level populates in one run within the default limits.
- `kit.spawn_points` now measures spawn exposure and spawn-to-spawn sight exactly as the design grader's spawn check (G19) does, on the compiled level (a private build when the brushes changed since the last one), and picks sheltered spots facing a way out, 8–15 m apart where they fit; the result's `report.measure` says what was measured.
- `kit.items` now follows the whole level's density: it aims at about 1.6 items per 100 m² of the level's playable floor (measured as the grader measures it) less the items already there, so calling it area by area adds up to one economy instead of a full set per call. `count` is now the number of items placed (`by_category` holds the split), `per100` counts only the call's spaces, and `level_per100` gives the level's density.
