Glacier Help & Feature Reference

Glacier is a modern, from-scratch level editor for Red Faction (2001) .rfl levels — a clean-room reimplementation (not stock RED.exe) that aims for stock-RED editor parity, Alpine Faction parity, and a layer of modern conveniences. This reference is fully offline; every link here jumps within the page.

Need a hand or want to share your work? Join the community on Discord (also on the Help menu).

1. Getting started

The first time you launch Glacier a short first-run wizard helps you point the editor at your game files. Nothing here redistributes game assets — Glacier reads textures, meshes and .tbl tables directly from your own Red Faction install.

The first-run wizard

  • Red Faction install — the folder whose .vpp packfiles hold the stock textures, meshes and tables. Optional: you can set it later in Settings, but textures and meshes will not resolve until it is set. Glacier probes common Steam/GOG and Wine locations automatically and reports how many VPPs it found.
  • Alpine Faction launcher — AlpineFactionLauncher.exe, the one executable play-tests run through. Glacier auto-detects it from the af:// protocol registration; otherwise browse to it. It may live outside the Red Faction folder.
  • Camera scheme — pick the navigation style you prefer (you can change it any time from the View menu). See Viewports & cameras.

Mounting game data

Once the install folder is set, Glacier mounts its VPP packfiles as a read-only virtual file system. alpinefaction.vpp is mounted above the base VPPs, so Alpine assets supersede stock ones exactly as the game resolves them. Use Tools ▸ Reload Textures / Reload Meshes to rescan without restarting.

Alpine Faction unlocks Alpine-only editor features, and multiplayer play-test launching runs through its launcher.

2. The interface

The workspace is a docked layout around a central viewport grid. Panels can be moved, floated, stacked into tabs and reset from View ▸ Reset Viewport Layout.

Docked panels

Outliner

Every object and brush grouped by type with counts, per-type and per-item show/hide, Jump To and View From. Sorted by name.

Properties

Context inspector for the current selection — brushes, faces, objects, events, lights, room effects, movers and more.

Asset Browser

Textures, meshes, sounds and prefabs: categories, filters, favourites, a large preview on hover, and drag any mesh or prefab straight into a viewport pane to place it where you drop it.

Object palette

Entities, clutter, items and event types, organised into category trees with hover mesh previews; drag a class into a pane to place it.

Link graph

An interactive node-graph editor of triggers, events, movers and their links — draggable, box-selectable, pan/zoom navigable.

Dependency graph

What references what: textures, meshes and assets used across the level, for packaging and cleanup.

Layers

Organise brushwork and objects into layers with show/hide/lock and solidity handling.

Statistics

Budget bars versus engine limits plus geometry counts, refreshed after every build and on demand.

Build output

The compile report — rooms, portals, faces, vertices, surfaces, lightmap pages, UIDs, timing and warnings.

Script console

A Lua REPL with history and colour-coded output; see Scripting.

Menus & the command palette

Everything lives on the menu bar (File, Edit, Select, View, Tools, Geometry, Level, Scripts, Help) and most commands are also on the toolbar. Press Ctrl+Shift+P for the command palette — a fuzzy search over every command that shows its bound key and runs it through the same dispatcher the menus use.

Notifications

Every message Glacier raises — a finished build, a warning, an error, a hint — always reaches the status bar and the Log panel. On top of that it can pop a brief toast in the bottom-right corner. Choose how much the toasts show from Settings ▸ General ▸ Toast notifications: Off, Errors only, Warnings, Info (the default) or Everything (including hints). The threshold gates only the toasts — the status bar and Log always record everything.

Undo application

Settings ▸ General ▸ Undo application sets how an undo is applied. Instant (the default) snaps straight to the target state in a single refresh; Replay walks visibly through each intermediate history entry. Both reach the same result — the choice governs plain Undo / Redo (Ctrl+Z / Ctrl+Y) as well as jumps through the edit history.

Locked brushes and objects are protected. Locking an item (the padlock in the Outliner or Layers panel, or Q / Shift+Q to lock / unlock) makes it unselectable and untransformable until you unlock it — a click that lands only on a locked item is refused with a hint — so you can work around fixed geometry without disturbing it. Unlock All (Shift+Q, or the Layers panel's Unlock button) also clears brush locks that shipped saved in the level file, so a file-locked brush becomes selectable and editable again.

3. Viewports & cameras

The viewport grid can show 1, 2 or 4 panes (cycle with F6, maximise the active pane with Tab). Each pane is independently a perspective 3D view or a top / front / side orthographic view.

Camera schemes

RED Classic

Stock RED navigation: numpad pitch / heading / slide, A/Z dolly, +/- ortho zoom, mouse-look on drag.

Modern FPS

WASD fly with mouse-look and a Shift speed boost — the default, familiar from modern editors and games.

Orbit

Tumble and dolly around the selection or a focus point, good for inspecting a piece of geometry from all sides.

UnrealEd

The UnrealEd-style mouse-button navigation many level designers already have in muscle memory: a left click selects, and a left drag flies the camera instead of drawing a selection box.

Continuous camera movement uses fixed held keys. The pitch / heading / slide / move-up-down / zoom / ortho-zoom motions are driven per-frame while you hold the key (numpad and A/Z/+/-). These are not rebindable — they appear in Settings ▸ Input for reference, and they are not offered in the command palette because a single click cannot reproduce a held movement.

Per-viewport view options

Each pane has its own options dropdown. Choices that apply to any view include Show Event Arrows (directional-event facing arrows, on by default), Show Links, Show Path Node Connections, Show Gizmo and Show Annotations. Perspective-only options include Draw Decals (project decal textures onto geometry; off by default), Draw Sky (draw the sky room like in-game), Show Fog, Room Rendering (scope which rooms draw) and Portal Faces (don't draw / see-thru / non-see-thru).

4. Editing modes

Glacier edits at several granularities. Switch modes from the toolbar, the View/mode hotkeys, or the palette.

ModeWhat you edit
BrushWhole brushes: create, move, clip, boolean, set brush type (solid / portal / detail).
FaceIndividual faces: extrude, bevel, texture and UV tools (the Texture/UV tab lives here).
VertexIndividual vertices: move, snap, weld.
EdgeEdges: bevel, extrude, collapse, loop / ring select, convert to faces or vertices.
ObjectPlaced objects and events: move, rotate, link, inspect, reorient, snap to camera.
GroupNamed groups of brushes and objects, moved and edited as a unit.
Edits keep every face flat. When a vertex, edge or face edit would bend a face off its plane, Glacier automatically triangulates that face — exactly as RED does — so brush faces never go non-planar. A move that slides along a face's own plane leaves it intact.
Selection follows the mode. Switching mode drops any selection the new mode cannot use — an object is deselected when you enter Brush, Face, Vertex or Edge mode. Group mode keeps both kinds: click a brush or an object to select it, and hold Ctrl to add across brushes and objects together. Clicking empty space, a locked item, or a wrong-kind item always clears the current selection.

5. Brush editing & operators

Brushes are the solid geometry of a level. Each brush carries a type that the compiler honours:

  • Solid — ordinary world geometry that walls off space and casts shadows.
  • Portal — a see-through boundary that splits rooms for visibility and culling.
  • Detail — decoration that does not carve the world BSP, so it never creates new rooms or leaks.
Portal brushes stay visible and selectable. An air portal brush (a portal that also carves) always shows its real textured faces, in every editing mode. A solid portal brush's faces instead follow the per-pane View ▸ Portal Faces option (don't draw / see-thru / non-see-thru). Either way, a portal brush is always selectable in every mode.

Boolean and construction operators available on brushes and selections include boolean (subtract / intersect), clip, carve, fuse, stretch, bend, twist, mirror, n-gon split and bridge. The interactive Draw Brush tool builds a brush in three stages (base outline, then height) with live grid snapping; it starts each launch set to create Air (carve) brushes — toggle Air / Solid on the Brush panel. Opening or creating a level always returns the active tool to Select.

Increment-based transforms. Move (M), rotate (R) and scale (S) work by the grid / rotation / scale increment for RED-parity precision. Hold Alt during a mouse drag to temporarily invert the magnet snap state (snap ↔ free).

6. Prefabs, groups & layers

Prefabs

A prefab is a reusable, parametric instance: save a selection of brushes and objects as a prefab, then place instances of it. Double-click a prefab tile (or drag it into a pane) to drop an instance in front of the camera, just like placing a mesh. Instances remember their source and their placement, so when you update the prefab you can propagate the change to every placed instance while keeping each one at the position and rotation you gave it. Update from Selection targets the prefab the selected objects belong to (or lets you pick one from a list) — no typing — with a prompt before overwriting instances you have modified locally. Prefabs live in your prefab library, browsable with thumbnails and a large hover preview.

A placed instance selects as one unit. Clicking any member selects the whole instance, and moving or rotating it drives every member together while keeping the instance's pose record current. To edit an individual member, double-click it — or click the padlock badge shown on the selected instance — to step inside; Esc (or clicking empty space) steps back out to unit level. Capture a new prefab from whatever is selected with File ▸ Save Selection As Prefab.

Groups

Groups bind brushes and objects into a named unit you can select and move together, import and export as .rfg files, and drag-drop into the viewport. Clicking any member selects the whole group as a unit; hold Alt to select the individual member instead (Ctrl likewise falls through to the single member, adding it to the selection). Locking a group protects every member from selection, movement and deletion until you unlock it, exactly as locking an individual item does.

Layers

Layers organise the level for authoring — show, hide and lock whole layers, with correct handling of brush solidity so hiding a layer never changes the compiled result.

7. To-Mesh conversion

Convert To Mesh Object turns selected brushwork into a static mesh object, matching the stock mesh-export behaviour. The To-Mesh dialog exposes the two toggles the conversion previously hard-wired, so you can control how faces and materials are emitted. Use it for decorative geometry that should render as a mesh rather than carve the world.

8. Objects & events

Objects are everything that is not world geometry: entities, items, clutter, lights, triggers, movers, particle emitters, ambient sounds, decals, cutscene path nodes, room effects, EAX environmental-audio zones and the full catalogue of events (148 event types).

Placing objects

Drag a class straight out of the Object palette (entities, clutter, items, events) or a mesh / prefab out of the Asset Browser and drop it into any viewport pane. A translucent ghost of the asset follows the cursor so you can see exactly what will land where. Dropped on a surface the object bottom-aligns to the face under the cursor (a pickup item instead floats 1 m above it); dropped in open space it lands in front of the camera. You can also place at the camera from the palette, staple an object to a face with S, or drop the last-placed kind at the cursor with P.

A new object's script name starts from a sensible default — the class name for entities, clutter and items, or the object type's name for everything else — and stays editable. Mesh objects can reference .v3m, .v3c and .vfx effect meshes, and .vfx files appear in the Asset Browser's Meshes tab alongside V3M / V3C models.

Every level needs a spawn point. A level's single Player Start marks where single-player begins; a new level is created with one already in place. Player Start (Move) in the Object palette moves it to the placement point — and creates one if the level has none. A level with no Player Start and no multiplayer respawn points has nowhere to spawn and renders black in-game; the level linter (Tools ▸ Run Level Linter) flags this.

Inspectors

The Properties panel shows a purpose-built inspector for each kind — events (with their typed fields and schema), lights, ambient sounds, coronas, meshes (including a per-slot texture override editor), EAX effect zones (environmental-audio reverb regions, each with a labelled inspector, listed in the Outliner like any other object) and Room Effects (sky / liquid / ambient-light, with the full liquid-property field set). Multi-selection edits apply across the selection with mixed-value handling. Every edit is a single undo step.

Links & the link graph

Wire triggers to events to movers by linking objects (K to link, Shift+K to break). The Link Graph panel visualises and edits these connections as a node graph; node positions persist per level in a sidecar next to the .rfl.

Movers, keyframes & cutscenes

A mover is one or more ordinary world brushes — a door, lift, elevator or rotating platform — bound into a moving group that animates along a keyframe path. The brushes stay normal, fully-editable world brushes; grouping them as a mover only adds the motion. Moving groups are listed and managed in the Moving Groups list.

Each mover follows a chain of keyframes. A new keyframe is seeded at the mover's own origin, lined up with the brush, and you drag it out to shape the path; Add @ Cam instead drops the keyframe at the camera. Keyframes are real, selectable objects — they show in the Outliner and draw on top of geometry so they can always be clicked. Deleting a keyframe never removes the mover's brush; deleting a mover's last keyframe dissolves the mover back to static geometry. Dissolve (on the Moving Groups list) turns any mover back into ordinary static brushes at any time.

The mover inspector exposes the full field set: Movement Type (one-way, ping-pong, loop, lift), Is Door, Rotate In Place, Starts Backwards, Use Travel Time as Speed, Force Orient, No Player Collide, the starting keyframe, and all four movement sounds — start, looping, stop and close — each with its own volume. Every keyframe carries its own travel, return-travel, pause, accel and decel times, a triggered-event UID, two item UIDs and a script name. A path preview ghost can be scrubbed along the path to check the motion.

Driving a mover. Link a trigger or event to the mover to set it moving; the link attaches to the mover's start keyframe, which is the connection the game follows. In the Link Graph a mover's internal structure is drawn as dashed edges, distinct from real links. Cutscenes drive the camera along path nodes. Copy and paste preserve every field, and fresh UIDs are assigned to clones so nothing collides.

9. Textures & UV

Browser & library

The texture browser lists everything mounted from the game data plus your custom subdirectories (shown as Custom - <dir> categories), with filters, favourites, tiled preview and display-size control. Supported formats include TGA (incl. 8-bit greyscale), VBM, DDS (DXT1/3/5), PNG, JPG and ATX (frame 0), resolved through the same supersede chain the game uses.

Drop a texture onto a face. Drag a texture tile from the browser onto a brush face in a viewport to apply it. If that face is part of the current face selection the texture applies to the whole selection; otherwise it applies to just the face you dropped on — always in a single undo step. (A locked brush is refused.)

Mapping & UV

From the Texture/UV tab (in Face mode) apply Box (Ctrl+Q), Planar and Cylinder (Ctrl+W) mapping, set pixels-per-meter, copy/paste UVs, and flip. Box, Planar and Cylinder project in world space, not brush-local, so a texture tiles continuously across adjacent brushes however each is rotated. Two Fit buttons snap the mapping to the texture tile: Fit stretches the face corner-to-corner over the tile (world projection), while Fit (Keep Aspect) scales uniformly so the texture is not distorted. Verify Textures (Tools menu) reports faces whose textures are missing from the mounted data before you build or package.

Planar map is a toolbar button, not a hotkey. In the RED Classic preset Ctrl+E is Extrude in Face mode, so Planar map has no key — use the Texture/UV panel button.

UV Unwrap editor

The UV Unwrap editor (Texture/UV panel ▸ UV Unwrap…) opens a 2D view of the selected faces' UV layout over their tiled texture. Every edit — including one completed gizmo drag — commits as a single undo step.

  • Selection modes — choose Vertices, Edges or Faces from the toolbar; the stored selection survives a mode switch. Click to pick, or drag a rubber-band box — hold Ctrl to add and Alt to remove.
  • Transform gizmo — hold M (move), R (rotate) or S (scale) with a non-empty selection to show a 2D gizmo at the selection centroid: drag the axis arrows or centre square (move), the rotation ring (rotate), or the axis boxes and centre/corner handle (per-axis vs uniform scale). The arrow keys still nudge by the increments while the key is held. With Grid Snap (G) on, a move lands the selection's centroid on the grid step and a rotation snaps to the Rotate° step; with it off both are continuous.
  • Increment selectors — the Rotate° and Grid toolbar controls are preset dropdowns with free entry, matching the main window's rotate/grid pickers; Move and Scale stay free-entry boxes.
  • Layout tools — Flip V/H, Align (Shift+V / Shift+H), Auto Unwrap (planar-project and pack the faces into the tile), Fit UVs (scale the selection to fill the base tile), decal-vs-texture display (D / T), Show Tiled, and Print → TGA.
  • Multiple faces — unwrap more than one face at once and each gets its own colour and a numbered label so you can tell them apart; hovering a face shows a readout and cross-highlights the matching face in the 3D viewport.
  • Navigation — wheel or Shift+right-drag to zoom, Shift+left-drag or middle-drag to pan, and Fit View to reframe.

10. Geometry building

Building compiles your brushwork into the room/portal BSP the engine renders. Run it from Geometry ▸ Build Geometry (Space in RED Classic, Ctrl+B in Modern).

Build Method

Shared BSP (default)

RED's authentic single accumulated shared BSP — the RED-faithful method, on by default. Measured equal-or-better than Incremental on every corpus level.

Incremental

Glacier's own modern accumulator. Fully functional and selectable from Geometry ▸ Build Method — nothing is removed.

Check for Holes & the build report

Check for Holes looks for leaks — gaps where the world is not sealed. The build report (Build Output panel) lists rooms, sub-rooms, portals, faces, vertices, surfaces, lightmap pages, UIDs, elapsed time and any warnings. The warnings are textual; hole-leak findings are click-to-navigate — click one to frame the leak in the viewport.

Saving never rebuilds or re-bakes. A save (Ctrl+S) writes exactly what you last built — RED-style — so rebuild geometry and recalculate lighting yourself after you change them. The one exception is an automatic re-seal of unsealed live-preview geometry immediately before the write (which resets its lightmaps to unbaked). If a build is still running the save is aborted — "retry when it finishes" — rather than writing half-built geometry.

11. Lighting

Glacier bakes lightmaps from your placed lights. Run a bake from Build ▸ Calculate Lightmaps (L) or the combined maps-and-light command. The Preview Lighting toggle re-bakes small levels with the exact CPU kernel for an accurate in-editor preview.

Edits keep the existing bake. Editing geometry after a bake does not throw the lightmaps away — the surrounding preview rebuild keeps them in place, now stale, until you recalculate lighting, exactly as RED does. Recalculate when you are ready for the shading to catch up.

Lightmap Method

The Level ▸ Lightmap Method flyout stays open while you toggle options. Pick one base method, then layer on any modifiers:

OptionWhat it does & when to use it
RED Classic (default)The stock direct-lighting bake. Fast, faithful to how original levels look. Use it for RED-parity and as your baseline.
Bounced — 1 / 2 BouncesAdds one or two passes of indirect light, so light spills realistically into shadowed areas. Use for softer, more natural interiors; two bounces is slower but fills deep spaces better.
Ambient OcclusionDarkens creases, corners and contact points to add depth. Use to make geometry read more solidly without moving any lights.
Soft ShadowsSoftens shadow edges instead of hard stock edges. Use for a gentler, higher-quality look, especially on large open shadows.
High-Resolution LightmapsRaises lightmap texel density so fine detail and small light cookies resolve crisply. Use on hero areas; it costs lightmap pages and bake time.
Seam Blend (cross-room)Blends lightmaps across room boundaries so a surface that spans a doorway is continuous. Use to kill visible seams at portals (mirrors Alpine's smooth-lights).
Corner Leak FixUses own-room ambient plus an edge-aware shadow bias to stop light bleeding through corners. Use when you see bright leaks at wall junctions.
Smooth Gutter NormalsWelds and angle-averages gutter normals so shading is smooth across lightmap gutters. Use to remove faceting artefacts on curved or beveled surfaces.
Movers cast shadows (default on)Bakes mover brushes — doors, lifts, elevators — as shadow occluders at their rest pose, so they cast static shadows. Turn it off for RED-authentic output (stock RED excludes movers from the lightmap shadow set).

12. Scripting (Lua)

Glacier embeds a Lua scripting engine exposed as a safe, versioned facade over the editor. Open the Script Console (a REPL) or the Script Editor window (syntax highlighting, Run / Dry-Run / Run-Selection). Scripts live in the portable scripts\ library beside the app, and ship with an example gallery (array grids, spiral stairs, mass texture replace, and more).

  • One run = one undo step. The whole run is a single undo transaction: success commits one undo node; an error or a Dry-Run rolls everything back, so a failed script leaves the level untouched.
  • Auto-registered commands. A user script with a --@name/--@id header registers itself as a command in the palette and Scripts menu, optionally bindable to a key with --@key.
  • Sandbox limits. No file, network or process access; runaway loops are bounded by an instruction budget and a timeout; destructive operations require an explicit allow-destructive opt-in and are disabled in Dry-Run.
Lua ops.playtest is editor-only. It drives the interactive editor's Alpine launch flow, so it is a no-op outside a running editor session. The full API — level, selection, assets, ops, lint, log, rng — is documented in docs/SCRIPTING-API.md, also reachable from the Scripts menu.

13. Playtesting

Launch straight into your level through Alpine Faction. Play Level (F7) and Play Level from Camera (F8) start single-player; Play in Multi (F9) and Play in Multi from Camera (F10) start a multiplayer session. The "from Camera" variants spawn you at the current viewport camera's exact position and heading, in both single-player and multiplayer — Glacier passes the pose through the game's own launch switches, so the first spawn lands where the camera looks.

Playtesting saves your level first, RED-style: the save writes exactly what you last built and does not re-bake, so run Geometry ▸ Build and Build ▸ Calculate Lighting before playtesting if you have changed geometry or lights. (Unsealed live-preview geometry is re-sealed automatically before the save, which resets its lightmaps to unbaked.)

Play-tests run through AlpineFactionLauncher.exe. On Linux the launch goes through a configurable template (default wine {exe} {args}) so the Windows launcher runs under Wine or Proton; staging paths flow through the VFS mount unchanged.

14. Import & export

Importing meshes

File ▸ Import Mesh brings in OBJ, FBX, glTF/GLB and DAE geometry, with a scale/axis/winding wizard. Import as one brush per material group, or as a batched static mesh object.

Exporting

Export the level or a selection to OBJ, glTF and VRML, or convert selections to mesh objects.

Packaging

The VPP packfile builder (File ▸ Create Level Packfile) collects your level and its referenced assets into a distributable .vpp, using the dependency scan to find what the level needs.

RFL versions. Glacier loads .rfl files from versions 180–305 and always saves version 305 (Alpine RED format). Opening a pre-Alpine (<300) level shows a non-blocking informational notice.

16. Troubleshooting & FAQ

Textures and meshes show as missing / pink

The Red Faction install folder is not set or does not contain the expected VPPs. Set it in Settings ▸ General, then Tools ▸ Reload Textures. Verify All Textures lists exactly which faces are unresolved.

Play-testing does nothing / can't find the launcher

Play-tests run through AlpineFactionLauncher.exe. Point Glacier at it in Settings (it is auto-detected from the af:// protocol registration). On Linux, check the launch template (default wine {exe} {args}).

Linux: Glacier won't start after extracting the tar.gz

The tar.gz is packaged on Windows, which cannot preserve the Unix executable bit. After extracting, run chmod +x Glacier once, then launch it. The AppImage does not need this — it is already executable.

My build has a leak / open edges

Run Check for Holes. Hole-leak findings in the build report are click-to-navigate — click one to frame the leak. Confirm surrounding brushes are Solid (not Detail) and that the shell is sealed.

An old level won't save the way it loaded

Glacier loads RFL versions 180–305 and always saves version 305 (Alpine RED format). Opening a pre-Alpine level is fine — it is upgraded on save.

A camera key won't rebind

Continuous camera movement (pitch / heading / slide / move / zoom / ortho zoom) uses fixed held keys by design and is not rebindable. Everything else is rebindable in Settings ▸ Input.

Where are my settings stored?

Next to the app when its folder is writable (portable). If the folder is read-only (e.g. installed under Program Files), Glacier falls back to your user profile and shows a one-time notice — nothing is lost.

Where can I get help or share levels?

Join the community on Discord. The Report Bug button in Help ▸ About opens the issue tracker in your browser.
